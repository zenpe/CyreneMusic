# 音频缓存约定

- 完整缓存使用平台、歌曲 ID（保留大小写）、规范化音质作为逻辑身份。解析脚本和播放 URL 不参与身份判断。私有音乐库额外按服务器、账号隔离，不持久化凭据。
- 音质字段表示请求档位，并不声称验证了上游实际码率。完整文件通过现有格式和完整性检查后才能提交。
- Android 片段使用完整播放 URL 的 SHA-256，保留查询参数；私有音乐库再加入账号范围。不同链接不拼接片段。继续使用已有响应校验，不增加 HEAD 请求。
- Android 从 Media3 已接收的数据复制并验证完整文件，不再发起整文件下载。其他平台沿用原有下载缓存链路。
- 默认总容量 512 MiB。完整文件、片段、临时写入及被读者占用的待删除文件均计入容量。空闲片段按 24 小时过期，并限制为 `min(总容量 / 5, 128 MiB)`，这是上限而非预留空间。
- 片段清理在初始化、网络源准备、读取结束及查询统计时执行。正在读取或复制的片段不参与空闲清理；总容量不足时停止可选缓存写入，继续网络播放。降低上限后，正在播放的文件保留到读者释放。
- 需要空间时先清理空闲片段，再淘汰不被占用的最久未访问完整文件。准备网络播放时按需回收空间，避免完整缓存占满后永久无法缓存新歌。
- “重新获取音频”只针对当前活动歌曲，绕过完整文件和解析 URL 缓存。新文件成功提交后才替换旧文件；失败保留旧文件。过期的刷新、清空前的写入及旧播放事务不能覆盖新结果。
- 完整文件不可原地修改。替换后旧文件等待全部读者释放再删除；写入清单采用原子替换。Android 重启时若发现中断替换留下的重复记录，以最新提交为准。
- 暂停保留待缓存请求；桌面端在暂停时释放刷新淘汰保护，恢复后仅同一代请求能重新取得保护并下载。清空缓存或新刷新会使旧请求失效。Android 的拖动、临时数据流关闭不取消刷新；实际切换播放源、停止或释放播放器才取消，成功写入后自然结束。
- 使用独立 `v4` 缓存目录，不迁移旧缓存。清理范围只包含此自动缓存目录，不操作下载文件或本地歌曲。

主要回归测试：`audio_cache_lifecycle_test.dart`、`audio_cache_identity_test.dart`、`playback_navigation_recovery_test.dart`，以及插件的 `CompleteAudioStoreTest`、`StreamCacheEvictionTest`、`StreamCacheManagerTest`。
