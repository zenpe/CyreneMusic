# 客户端请求后台巡检实施方案

- 日期：2026-11-17
- 状态：两端代码已实施，本地自动化验证完成；尚未发布或部署，真实后端与客户端联调仍需验收。
- 基础：现有按平台自动推荐、后台定时检测、客户端每 15 分钟检查清单均保留。

## 1. 最终交互

在设置页「自动推荐」卡片增加「请求后台巡检」，与现有「检查自动推荐更新／使用自动推荐」并列。

- **检查更新**：立即读取后台已经发布的推荐清单。
- **请求巡检**：申请提前执行后台检测；检测后仍由原有规则决定是否发布新清单。

按钮不要求先选中自动推荐，也不要求后台已经生成首份推荐；需要登录当前后端。没有登录时提示先登录，不自动跳转或切换音源。

点击后只在 HTTP 请求期间显示忙碌状态。受理后显示「已请求后台巡检，检测完成且满足推荐条件后将自动更新」。已有任务时显示「后台正在检测，无需重复请求」；限频时显示可以再次请求的时间。旧后端提示「当前后端暂不支持请求巡检」。

不增加平台选择、确认弹窗、任务详情页或持续轮询。当前播放不受影响；发布后的应用继续走原有定时检查、前台恢复检查和手动检查更新。

## 2. 后端最小改动

新增 `POST /lx/recommendation-check`，使用现有 Bearer 登录鉴权，普通登录用户可调用。请求无需携带歌曲、脚本、平台或管理员控制参数。

在 `Automatic` 增加独立的客户端请求方法，复用调度器和共享 Controller；HTTP 处理函数只登记调度意图，不直接启动 worker。不要直接开放管理员 `Request`：该方法会清除 `RetryAt`，属于管理员干预行为。

处理顺序在现有锁内完成：

1. 自动推荐未启用、已暂停或 Controller 不可用：明确拒绝，不改变调度状态。
2. 已有自动检测任务或已登记请求：返回已有任务／已登记，不追加任务。管理员手动检测占用 Controller 时返回忙碌，不抢占。
3. 检查全局请求间隔，默认 30 分钟；所有账号共享，服务重启后仍有效。
4. 登记一次提前巡检意图并保存成功，再返回已受理。

提前巡检覆盖 QQ、网易，沿用现有「检查当前推荐及候选 → 分批扫描其他候选」流程。已有完整扫描队列继续执行，不重建队列或重复已完成批次；没有推荐的平台也能进入原有候选扫描。只检查当前推荐不足以发现替代者，因此不能把按钮实现成仅刷新当前推荐健康状态。

保留现有失败退避 `RetryAt`、分片续跑 `ResumeAt`、任务预算、串行批次、至少两轮确认及确认间隔。请求表示提前登记，不承诺立即开跑或立即换源。优先级仍由原调度器管理，不能插入一个绕开预算的任务执行通道。

复用运行状态文件保存待处理意图和最近受理时间；同一时刻最多一份待处理意图。不新增数据库、依赖或独立任务系统。现有 `RequestedID` 会在部分批次完成后清除，不能把它当成覆盖两个平台全过程的任务进度 ID；本次接口不提供按 ID 查询完成状态。

建议接口结果：

| HTTP | code | 客户端行为 |
| --- | --- | --- |
| 202 | accepted | 提示已受理 |
| 200 | already_running / already_requested | 提示无需重复请求 |
| 401 | unauthorized | 提示登录当前后端 |
| 409 | disabled / paused / busy | 展示原因 |
| 429 | cooldown | 根据 `Retry-After` 和 `retryAfterSeconds` 提示等待 |

统一使用现有 JSON 响应结构。接口不暴露脚本凭证、worker 日志、管理员状态或控制权限。现有公开 GET 接口的鉴权行为不变。

## 3. 客户端最小改动

在推荐服务增加 `requestAutomaticCheck()`，使用 `ApiClient.requestJson` 的登录态 POST；不要修改现有公开清单／脚本下载逻辑为统一携带认证。服务方法可独立于自动推荐 Router 调用，避免请求巡检时被迫启用音源。

设置页增加按钮及请求期间的点击锁，处理上表状态、旧服务 404/405 和网络错误。请求完成时检查页面生命周期和后端地址／版本，丢弃切换后端前发出的旧响应。

提交成功不修改已选音源、不清理 URL 或完整音频缓存、不直接刷新解析器、不重启播放。按钮也不接入播放失败事件。

## 4. 实施顺序与验收

1. 后端先实现独立受理方法、鉴权接口和必要测试。
2. 客户端实现服务调用、按钮和结果提示。
3. 在同一套测试后端完成联调，再按原有发布流程交付两端。

必须验证：

- 未登录不可触发，普通用户可触发，无管理员权限泄露；关闭管理后台后仍可工作。
- 多用户并发只受理一次；运行中合并；手动检测不被抢占；限频跨重启有效。
- 暂停、关闭、故障退避、分片间隔及确认间隔均不能被按钮绕过。
- 无首份推荐时能启动正常候选扫描；已有扫描不重置进度；受理后重启不丢失意图。
- 请求丢包后重试不会重复排队；保存失败不能返回已受理。
- 客户端正确处理未登录、限频、忙碌、旧服务及后端切换；播放和已缓存音频保持正常。
- 测试中完成检测并形成符合原规则的新清单，客户端通过既有检查更新链路取得并应用；检测未发现更优候选时保留原推荐。

这次只新增用户主动申请提前巡检的入口。定时检测仍负责无人值守维护，15 分钟清单检查仍负责取得已发布结果；本次不增加播放失败上报、自动触发巡检、跨平台换歌或客户端备用源调度。
