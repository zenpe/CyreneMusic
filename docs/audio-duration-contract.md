# 歌曲时长传递与资源核验

实施日期：2026-11-16。涉及客户端 `F:/CyreneMusic` 与后端 `F:/cyapi-go`。

## 边界

平台歌曲资料中的预期时长沿现有模型、接口、歌单、收藏、历史和播放会话传递。客户端与后台分别在集中适配入口生成 LX `interval`。资源时长是独立证据，不回写目标歌曲的预期时长。

本次不添加自动跨平台搜索、脚本轮换、播放前整文件下载或新的运行依赖。播放器调度与重试策略保持原有结构。

## 数据契约

- `durationMs` 为可选整数毫秒，范围为 `1..86400000`；缺失、零及异常值代表未知。旧客户端与旧记录均可缺省。
- LX `interval` 由已知时长向下取整到秒，格式为 `MM:SS`，例如 `212000 → 03:32`。不根据文件大小推造预期时长。
- 后台检测样例的 `expectedDurationMs` 是唯一时长来源。运行 worker 时复制 `musicInfo`，剔除旧的时长别名，再生成 `interval`；既有样例不需要手工修改。
- Go 与 Dart 各自实现无副作用的格式转换与时长判断，共用相同的 JSON 测试数据：客户端 `test/fixtures/audio_duration_contract.json`，后端 `internal/music/testdata/audio_duration_contract.json`。
- 已知资源时长不足预期的 80%，并且相差超过 15 秒，报告为“疑似短音频”。边界值沿用已有后台规则。未发现明显偏短不代表歌曲身份正确，也不代表音频已完整解码。

## 客户端

- `Track`、`SongDetail` 及歌单、收藏、历史的转换保留时长。播放队列恢复沿用 `Track` 的 JSON，无需升级会话格式。
- 搜索、歌单、专辑、推荐等已知数据入口保留平台的时长字段；单位在平台边界明确转换。
- 复用 `TrackMetadataService` 的缓存、并发限制、失败冷却和身份隔离。播放时允许后台补全时长，不等待该请求；普通列表不会仅因缺少时长而新增补全请求。
- 旧记录第一次播放时，资料可能尚未补齐，仍可能无法排除短资源。这是非阻塞补全的明确限制。已完成的资料会保存到元数据缓存，后续解析可使用。
- 已知预期时长发生变化时，解析器不复用按旧时长输入得到的内存 URL 或在途请求；新输入会到达脚本。
- 正常缓存写入仅在有可靠的资源时长证据时判短。播放器提供的证据要求已稳定播放、没有待切歌曲、歌曲身份与 URL 均匹配当前活动资源，且进度位于时长范围内；在异步写入前同步捕获。
- 判短时跳过本次缓存写入，不停止播放。未知证据保持现有行为；不全量删除历史缓存，也不将旧缓存默认判为有效歌曲。
- 本次桌面缓存准入不改变 Android 原生流缓存路径。

## 后台资源核验

- 保留已有请求与读取预算。只有在预算内读到 EOF，且 HTTP 200/206 的长度及 Range 表明完整表示时，才认定取得完整资源。
- 完整 MP3 增加逐帧时长计算，覆盖没有 Xing/VBRI 帧数头的 CBR 文件；支持常规 ID3v2 前缀与 ID3v1 尾标签。截断帧、未知尾部、采样率变化等情况不凭前缀推算整曲时长。
- 部分响应继续使用已有的可靠格式元数据；缺少依据时，时长保持未知。
- 完整资源记录 SHA256 并在管理页面展示，便于对照不同样例是否返回相同文件。大小相同或 URL 相同不直接等于歌曲错误。
- 格式识别、时长证据与最终判断分别保留；没有将“HTTP 成功”“可识别格式”升级为“歌曲正确”。

## 数据库兼容与部署

后端新增 `0004_song_duration.sql`，分别为 SQLite/PostgreSQL 的歌曲目录与收藏添加可空 `duration_ms`。新旧接口字段兼容；旧客户端提交缺省时长不会清除歌曲目录已有值。没有后台全量回填。

部署必须按后端既有升级流程，由新二进制显式执行 `cyapi migrate --config <配置文件>` 后再启动。生产部署、发布推荐脚本和发行版均未由本次本地实施自动执行。数据库迁移后，回滚须遵循既有 schema 兼容流程。

## 回归重点

1. `212000` 毫秒经过接口、持久化与会话恢复后仍生成 `03:32`。
2. 相同契约数据在 Go/Dart 中得到相同的间隔及阈值判断。
3. 后台真实 Goja worker 将已保存样例的预期时长传给脚本，不修改样例原内容。
4. 297 个 48 kHz MPEG 帧组成的 171072 字节 MP3 被读出约 `7128 ms`；相同字节若只是大文件前缀，不按短音频下结论。
5. 时长补全后不复用旧输入的解析缓存；旧在途请求不会覆盖新结果。
6. 稳定播放的短资源不触发正常缓存下载；切到正常歌曲后不沿用前一首的短时长证据。

## 本地验证结果

- 客户端核心回归 159 项，以及请求生命周期、手动换源、收藏的 11 项回归通过。
- 原推荐脚本 2.1.0 的真实 QuickJS/HTTP 回环测试通过：使用生产 `buildLxMusicInfo(durationMs: 212000)` 后拒绝 171072 字节的模拟资源；缺少时长的对照组仍接受。此次为隔离复现，没有请求生产解析接口。
- `go test ./...` 与管理页面 5 项 Node 测试通过。SQLite 迁移与新旧数据写入已执行集成测试；没有配置 PostgreSQL 实库，其条件集成测试跳过。
- Go/Dart 契约样例文件逐字节一致。静态检查没有新增问题；现有 `proxy_service.dart` 的一条提示保留。
- Windows Release 构建成功，产物已同步至 `build/windows/x64/runner/Release/cyrene_music.exe`。验证目录与原 Release 目录的 59 个产物文件摘要一致。临时 CMake 输出配置已恢复，应用版本未调整。
- 后端代码尚未部署，线上拿到新增时长字段需要配套更新后端并执行迁移。旧后端缺少字段时，客户端保持“时长未知”。
