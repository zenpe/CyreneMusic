# 应用功能与性能测试记录（2026-10-15）

## 结论与范围

本轮以当前未提交工作区为基线，进行了 Android 模拟器真实操作、真实音源请求、后台媒体控制、网络故障注入、真实后端歌单 CRUD、静态检查和测试回归。发现两项可复现的界面缺陷；外部解析请求仍存在超时与冷切等待，不应宣称“所有歌曲秒切”或已经完成全平台发布验收。

环境：Android 15 模拟器 emulator-5554、1080×2400、单 CPU。模拟器没有音频输出，播放验证以原生 ready、业务状态、进度推进和目标歌曲一致性为依据，不能代替真机外放听感。Windows 上运行的是旧 release，未把它当作最新版本实测。iOS 真机、车机、电池优化长期后台、长时间内存趋势不在本轮已验证范围。

初始测试阶段未修改产品代码；随后按用户要求修复下述两项界面缺陷，复测结果见文末。未卸载应用或清空账号、音源。临时测试歌单已经删除。测试恢复了播放队列、模式、音量、缓存开关、搜索历史、主题和设备旋转/飞行模式。

## 已确认缺陷

### P2：发现页歌单卡片底部溢出

修复状态：已修复。Material/Cupertino 网格改用方形封面高度加实际字体度量计算卡片高度，并统一布局计算与卡片使用的文字样式。模拟器两种主题横竖屏、正常/1.5 倍系统字体下，未再捕获发现页卡片溢出。Cupertino 实际卡片回归测试覆盖 320～1200 宽度及 1～3 倍字体。

- Cupertino 主题竖屏，两行歌单标题与创建者文字使卡片溢出，实测约 9～12 像素。
- Material 主题横屏也出现卡片底部溢出，采集到约 8～25 像素。
- 涉及 `lib/widgets/cupertino/cupertino_discover_widgets.dart` 的方形封面 + Expanded 信息区，以及 `lib/pages/discover_page.dart` 中固定 `childAspectRatio` 的网格。
- 建议按卡片宽度、封面高度、标题行高、创建者行高和内边距计算卡片高度；保留两行标题，不用单纯裁剪或隐藏溢出掩盖问题，同时验证字体放大。
- 证据：`build/qa-ui-errors.log`、`build/qa-cupertino-0-discover.png`，以及横屏截图。调试版溢出警示不会原样显示在 release，但空间不足的问题仍需处理。

### P2：最近播放缺失封面时显示错误内容

修复状态：已修复。两种首页布局复用封面占位处理，空/无效地址不创建网络图片请求，有效地址加载失败显示同一音乐图标占位。模拟器首页截图确认缺封面占位正常，回归测试覆盖空串、空白、非 URL、缺 host 和非 HTTP 地址。

- 在测试曲目 `picUrl: ''` 的情况下，首页最近播放大封面出现红叉与 `No host specified in URI`。
- 涉及 `lib/pages/home_page/home_widgets.dart` 中直接使用 `history.first.picUrl` 且缺少错误占位的 `CachedNetworkImage`（约第 472、582 行）。
- 这是缺封面边界数据的可复现问题，不代表普通有效封面 URL 全部失败。
- 建议无效/空 URL 直接显示统一占位，有效 URL 加载失败也显示相同占位。
- 证据：`build/qa-home-initial.png`。

## 播放耗时

以下是 debug 模式、真实外部音源、同一模拟器上的少量观测值，不是统计性能承诺。

| 场景 | 第一轮 | 第二轮 | 第三轮 |
| --- | ---: | ---: | ---: |
| QQ 首播 | 6841 ms | 3105 ms | 6425 ms |
| 早切网易 | 5895 ms | 3375 ms | 6999 ms |
| 预缓冲后下一首 | 850 ms | 620 ms | 536 ms |
| 连续点选最终目标 | 1984 ms | 未执行完 | 1260 ms |
| 自动下一首 | 1390 ms | 候选超时后跳过恢复播放 | 907 ms |

自动切歌计时包含 seek 及旧曲剩余约 500 ms，不能直接与手动切换时长比较。第二轮脚本原本要求自动切换后一定播放指定曲目，遇到应用正常跳过失败候选时报告 StateError；结构化日志证实请求超时、候选跳过和后续 playing 提交，不能据此误报为应用卡死。

第三轮原生 set-source：首播 1341 ms、早切 1282 ms、预缓冲接管 344 ms。冷切总耗时明显大于原生装载耗时；仍应结合解析/排队分段日志改善冷态体验，而不是把所有慢切归因于播放器。

### Release 测试包说明

项目 release 配置固定 ARM64。首次指定 `android-x64` 构建与该配置冲突，产物缺失 `libflutter.so`，启动退出；这是测试构建组合错误，不计为正常 ARM64 发布包的播放崩溃。随后使用忽略目录中的 `build/qa-x64.init.gradle`，仅在该次 Gradle 构建覆盖 release ABI 为 x86_64，确认 APK 含有 `libapp.so`、`libflutter.so` 与 QuickJS 库后继续测试，没有修改项目生产 ABI 配置。

为保留模拟器现有账号配置，QA release APK 使用与已装 debug 相同的测试证书重签；AOT release 内容未改。`build/qa-release-x64-same-cert.apk` 是模拟器 QA 专用包，不能作为 ARM64 真机发布包分发。

### Release 测量结果

- 三次冷启动均成功，Android `am start -W` TotalTime 分别 6465、4140、4368 ms；中位数 4368 ms。
- 启动后经 UIAutomation 观察到首页的时刻分别约 11.79、11.39、12.11 秒；该数值包含树采集、等待 UI 空闲等测试开销，只能作为“在此时刻已观察到首页”的上界，不能等同于首帧耗时。
- 首页、发现、我的、设置实际点击共三轮（12 次），三次横屏/竖屏往返、前后台恢复成功。正确 ABI 的测试包期间未新增 APP CRASH 或 ANR；exit-info 中的 force-stop 为冷启动测试主动操作。
- PSS：初始 151345 KiB（147.8 MiB），三轮浏览后 264571 KiB（258.4 MiB），短暂回首页静置后 261746 KiB（255.6 MiB）。内存有增长，但涉及页面/图片缓存，且未做长时间稳态与强制 GC 对照，不能证明泄漏或证明无泄漏。
- RSS：初始 251.9 MiB，三轮浏览后 367.1 MiB，静置后 364.9 MiB。
- `dumpsys cpuinfo` 最终快照中应用未达到列出阈值；不能据此给出 CPU 0% 或持续播放功耗结论。
- `gfxinfo` 仅采到 33 个 Android HWUI 帧，其中标记慢帧 31 个（93.94%），p50 34 ms、p95 101 ms；这是稀疏的宿主绘制样本，不能代表 Flutter Surface 的全部渲染帧。存在性能待核实信号，未把它作为正式版流畅度达标证据。
- 模拟器为单核，无法直接外推普通真机冷启动和帧率。建议用 ARM64 真机 profile/Perfetto 对启动、页面动画和持续播放补测后，才做性能发布签收。

证据：`build/qa-release-smoke.json`、`build/qa-release-memory-*.txt`、`build/qa-release-gfxinfo.txt`、`build/qa-release-exit-info.txt`、`build/qa-release-lastanr.txt`。测试结束恢复同证书 debug APK，保留原账号、音源及本地配置。

## 界面修复后复测补充

两项新增回归及原有 Cupertino 首页布局回归共 3 项通过；静态检查无问题。模拟器通过热重启加载修复代码后，实际点击发现页，在两种主题、横竖屏、1/1.5 倍系统字体共 8 个组合中检查并截图。调试 APK 构建成功并覆盖安装，保留现有配置。

复测另外捕获过一项独立问题：1.5 倍字体横竖屏切换期间，`lib/widgets/mini_player.dart` 的歌曲信息 Column 在最多 35px 高的约束下发生 22px 底部溢出。堆栈已确认不是发现页卡片。

新增 MiniPlayer 实际组件回归，使用无自动播放的会话恢复提供真实显示歌曲，覆盖 320/360px 竖屏与 800px 横屏、1/1.5/2/3 倍字体切换，确认组件可见、歌曲信息存在、无溢出且大字体时高度增大。连同原有三项界面回归共 4 项通过，静态检查无问题。模拟器保留可见 MiniPlayer 复测两种主题、横竖屏、1/1.5 倍字体，共 8 组未捕获 Flutter 布局异常。证据为 `build/mini-player-layout-tests-final.log`、`build/mini-player-layout-analyze.log`、`build/mini-player-layout-emulator.log`；debug APK 重新构建并覆盖安装。
