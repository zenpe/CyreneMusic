# 均衡器设计与验证边界

## 目标

均衡器是可失败的附加音效，不进入播放启动预算，不因音效失败停止播放或重建播放器。
保留 Android 原生 Equalizer 与桌面 mpv 音效实现；本次不更换播放引擎、不引入自动音量补偿。

## 设置与设备能力

- 设置保存为频率/增益点组成的曲线，旧十段数组迁移为带频率的曲线。
- Android 获取当前音频会话实际支持的频段；按对数频率插值，每个原生频段仅设置一次。
- 滑块范围取设备能力与应用 ±12 dB 上限的交集。桌面仍使用标准十段。
- 预设保留原始曲线，换设备只重新映射；用户编辑滑块时生成当前频段的新曲线。
- 请求启用与实际生效状态分开；等待设备、应用中、旁路、关闭和失败均有对应提示。
- 零增益曲线禁用音效处理，但保留 Android 效果对象，避免反复越过零点时重建。

## 调度与生命周期

- 设置立即反馈，应用合并窗口 50 ms，保存合并窗口 250 ms；离开设置页面立即提交保存。
- Dart 单次应用在途，保留最新设置；旧后端结果和旧设置结果不能覆盖当前状态。
- Android 插件绑定 FlutterEngine，Activity 销毁不再释放仍在后台使用的均衡器。
- 原生操作在独立串行线程执行，仅保留一个待执行任务；过期任务清理后才开始下一任务。
- 原生调用等待上限 500 ms；超时按会话及请求 ID 失效，不宣称中断已经进入系统的原生调用。
- 系统音效服务长期挂起时显示失败，播放不等待该线程；不创建更多线程来绕过挂起。
- 原生设备可能量化增益，不以逐毫贝精确回读相等作为成功必要条件。

## 验证

自动化覆盖曲线校验/映射、旧设置迁移、能力变化、应用失败仍保存、最新设置合并、旧后端隔离、
超时后的定向失效及重试，并回归播放恢复与切歌失败处理。Android Kotlin 编译检查原生集成。

真机听感、不同厂商音效控制权竞争、后台长时间播放及 Activity 重建仍需设备验证；
编译及 mock 测试不代表这些硬件场景已经验证。
