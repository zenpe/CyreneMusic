# 播放链路审查与修复

日期：2026-11-03。范围：选歌、音源解析、缓存与预加载、原生装载、播放控制、失败恢复和提示。桌面使用 MediaKit 与本地代理，Android 使用 Media3 直连。

## 确认的问题与处理

| 问题 | 处理 |
| --- | --- |
| Windows 装载未实现 `EngineLoadControl`，新选择可能等待旧装载结束 | 接入已有取消接口；取消后的播放器句柄退出使用，迟到结果不能继续播放 |
| 初始化、打开媒体、启动播放各自等待，无法约束总耗时 | 共用单次装载预算；控制操作和清理都有界限 |
| Windows 启动时同步状态已就绪，却仍等待新的流事件 | 订阅后立即检查当前播放与缓冲状态 |
| 代理的 HTTP 状态丢失，只剩 `Failed to open` | 按独立播放路由保留传输阶段与状态，交给现有协调器决定恢复 |
| 根据整条错误文本包含 401/403 判断权限，可能命中签名 URL 的数字 | 排除 URL，只解析明确的 HTTP 状态字段；代理事实优先 |
| 同一错误既通过流回调上报又通过装载异常抛出 | 协调器按播放代次只处理一次，避免重复消耗预算和提前弹错 |
| 原始播放器错误和带鉴权参数的长 URL 进入提示 | 统一生成面向用户的短提示；诊断日志记录状态、阶段、耗时并隐藏链接 |
| 代理启动/停止并发、固定端口与 localhost 地址不一致 | 合并并发启动，停止使旧启动失效；绑定 IPv4 回环与系统分配端口 |
| 切歌后上游连接可能继续占用资源 | 每个播放路由拥有连接；取消、替换、停止和销毁时释放该路由与 HLS 子资源 |
| 代理缺少连接与读取期限 | 分别约束响应头和流读取，不在代理层自行重试 |
| HLS 重定向后相对地址基准不正确 | 使用最终响应地址解析分片和密钥地址，保持父子路由的取消范围一致 |

## 统一规则

- 播放协调器管理用户意图、重试次数和切歌预算；解析器、代理和原生引擎提供结果或错误事实。
- 401/403/404/410 可以在剩余预算内重新获取一次地址；拒绝再次装载相同的已拒绝地址。429 不自动重试。5xx 和网络失败按已有预算处理。
- 原生控制超时不代表 URL 失效，不据此反复请求音源。
- 失败、取消和音源切换不能让旧任务恢复播放，也不能将单首失败升级为整个音源不可用。
- 保留已存在的“解析失败时继续播放旧歌曲”行为：界面继续展示实际播放的旧歌，失败提示对应目标歌曲。这不是进度残留，应保持歌名与进度一致。
- 不修改已有的手动下一首、自动续播候选范围和播放模式规则。

## 验证

新增与扩展的验证覆盖：

- 真实回环 HTTP：Range、HEAD、鉴权头隔离、401/403/404/410/429/503、响应头超时、读取超时、取消、停止与启动竞争、重定向 HLS 和超过 256 个分片的清单。
- Windows 控制测试：初始化或打开媒体期间取消、迟到完成、装载中暂停、同步就绪状态、跨阶段总期限。
- 统一播放流程：HTTP 失败在直接选歌与手动切歌时的预算限制、缓存绕过、重复错误去重、恢复成功不弹错、下一次操作恢复、意外异常不泄露 URL。
- Windows 真实 libmpv：代理音频实际播放与进度、404/429 后继续播放下一首、挂起连接被新选择取消。
- 已有 Android 引擎、音源切换、缓存、预加载、歌词投影、队列、暂停、恢复与界面状态回归。
